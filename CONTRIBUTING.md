# Version Control and Contribution Guide

## Purpose

This repository uses simple Git practices to keep the learning process visible and the portfolio easy to review.

## Branches

- `main`: reviewed portfolio content.
- Optional short-lived branches: `feature/prompt-library`, `feature/ux-case-study`, or `fix/copy-accuracy`.

Advanced branching is optional for this training project.

## Commit Guidelines

- Make one focused change per commit.
- Use an imperative, descriptive message.
- Do not commit confidential data, personal identifiers, access tokens, or real airport records.
- Review Markdown formatting and links before committing.

### Recommended commit sequence

```text
docs: create project overview and responsible-use statement
feat: add reusable prompt engineering library
feat: document professional writing workflow
feat: transform synthetic notes into product brief
feat: add four-week product design plan
test: apply verification checklist to match notification
docs: document responsible AI and data classification
docs: add personal AI integration plan
docs: complete UX case study and product documentation
chore: run final repository review
```

## Review Checklist

- Required section is complete.
- Claims are supported or labeled as assumptions.
- Missing information uses `[Not Specified]`.
- Synthetic evidence is not presented as real research.
- No sensitive or confidential information is present.
- AI-assisted content includes human review.
- Links and tables render correctly.
