# Planning Workflow

## Goal

Create and evaluate a privacy-aware MVP prototype for Sanad's airport lost-item reporting and ownership-verification journey within four weeks.

## Mechanisms

1. Structured discovery using synthetic scenarios and clearly labeled assumptions.
2. Privacy-by-design separation between general descriptors and protected evidence.
3. Iterative flow and interface design.
4. Human review at product, accessibility, privacy, and operational decision points.
5. Conceptual usability testing before any production recommendation.

## Phases and Tasks

| Phase | Tasks | Primary owner | Output | Completion criterion |
|---|---|---|---|---|
| 1. Frame | Define problem, user, scope, exclusions, assumptions, and risks. | UX/Product Designer | Approved project brief | Scope and unknowns are visible. |
| 2. Structure | Map current journey, proposed flow, system states, and service handoffs. | UX/Product Designer | Journey map and user flow | Main and recovery paths are represented. |
| 3. Protect | Classify data and define where protected evidence and employee review appear. | UX/Product Designer + privacy reviewer | Data classification and trust rules | No protected detail appears in match previews. |
| 4. Prototype | Produce low-fidelity then high-fidelity screens and bilingual UX copy. | UX/Product Designer | Clickable conceptual prototype | Primary flow can be completed end to end. |
| 5. Evaluate | Run a conceptual usability review and expert checklist; document limitations. | UX/Product Designer | Findings and severity list | Findings are evidence-based and not fabricated. |
| 6. Refine | Resolve critical issues and document remaining dependencies. | UX/Product Designer | Revised prototype and decision log | All critical prototype issues are closed or escalated. |
| 7. Handoff | Package specifications, system states, content rules, and open policy questions. | UX/Product Designer | Handoff documentation | Another reviewer can follow the logic without verbal explanation. |

## Four-Week Schedule

### Week 1 - Frame and Structure

- Finalize problem statement and MVP boundaries.
- Document the provisional persona as a hypothesis.
- Build the current-state and proposed journeys.
- Identify missing operational evidence.

### Week 2 - Flow and Privacy

- Create lost-item and employee-review flows.
- Define report states and recovery paths.
- Separate general descriptors from protected evidence.
- Review potential data exposure points.

### Week 3 - Prototype

- Create wireframes for the primary journey.
- Draft bilingual status and error messages.
- Build high-fidelity priority screens.
- Complete an accessibility and consistency review.

### Week 4 - Evaluate and Refine

- Run a conceptual moderated prototype test with fictional tasks.
- Consolidate findings without presenting them as production evidence.
- Correct critical and high-severity issues.
- Finalize documentation and decision log.

## Decision Ownership

AI may help break work into tasks or identify missing considerations. The human designer decides scope, prioritization, accepted risk, design direction, and whether evidence is sufficient to proceed.
